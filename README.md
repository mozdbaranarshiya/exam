# آزمون‌ساز معلمان

سامانه فارسی و راست‌به‌چپ برای GitHub Pages با پایگاه داده و احراز هویت Supabase. معلم با نام کاربری و رمز عبور وارد می‌شود، سؤال تستی یا تشریحی و بارم می‌سازد و لینک `https://mozdbaranarshiya.github.io/exam/id/{id}` را برای کلاس می‌فرستد. دانش‌آموز نام و نام خانوادگی و پاسخ‌ها را ثبت می‌کند. تست‌ها در سرور تصحیح می‌شوند؛ نمره تشریحی را معلم وارد می‌کند.

پروژه Supabase معرفی‌شده (`pukanizbahswrupscfmg`) راه‌اندازی شده است: مهاجرت اولیه و مهاجرت افزایشی نمره‌دهی، تنظیمات ورود با نام کاربری و تابع `exam-api` نصب و با درخواست‌های واقعی بررسی شدند. برای همین پروژه SQL اولیه را دوباره اجرا نکنید. مراحل نصب زیر برای راه‌اندازی پروژه تازه یا بررسی تنظیمات‌اند. انتشار GitHub Pages جداگانه انجام می‌شود.

## راه‌اندازی Supabase

1. فایل مهاجرت در `supabase/migrations/` را با SQL Editor پروژه Supabase اجرا کنید. جزئیات و کنترل دسترسی در [راهنمای پایگاه داده](supabase/README.md) آمده است.
2. در Authentication → Providers → Email، ثبت‌نام با ایمیل را فعال و **Confirm email** را غیرفعال کنید. برای ورود با نام کاربری، ایمیل داخلی `username@teachers.exam.invalid` استفاده می‌شود؛ ایمیل واقعی و بازیابی رمز از طریق ایمیل در این نسخه وجود ندارد. شماره موبایل فقط اطلاعات پروفایل است و تأیید SMS ندارد.
3. نشانی پروژه و کلید **عمومی** در `config.js` قرار دارد. این کلید عمومی انتشارپذیر است؛ هیچ کلید `service_role`، رمز پایگاه داده یا کلید شخصی معلم را در فایل‌های سایت قرار ندهید.
4. گردش کامل ثبت‌نام معلم، ساخت آزمون، ثبت پاسخ دانش‌آموز و تصحیح را روی پروژه اجرا کنید. آزمون‌های محلی با داده‌های ساختگی، اتصال زنده پروژه را اثبات نمی‌کنند.

## اجرا و بررسی محلی

به Node.js 24 و Python 3 نیاز است. برنامه وابستگی تولیدی و مرحله build ندارد.

```sh
cd /workspace/exam
npm run check
npm test
npm run dev
```

سرور پوشه والد را سرو می‌کند و برنامه در مسیر `/exam/` قرار دارد. مسیرهای دانش‌آموز در GitHub Pages با `404.html` به برنامه بازمی‌گردند؛ شناسه از query خوانده و مسیر ظاهری `/exam/id/{id}` بازیابی می‌شود. سرور ساده Python برای مسیرهای ناشناخته، `404.html` سفارشی را خودکار اجرا نمی‌کند؛ برای بررسی محلی آزمون از `/exam/?exam={id}` استفاده کنید.

برای اجرای همه بررسی‌ها، از جمله مرورگر و PostgreSQL محلی، با ابزارهای خارج از مخزن:

```sh
mkdir -p /workspace/.exam-tools
npm install --prefix /workspace/.exam-tools --cache /tmp/exam-npm-cache --ignore-scripts --no-audit --no-fund --save-exact playwright@1.63.0 @electric-sql/pglite@0.5.8
cd /workspace/exam
EXAM_SQL_TOOLS=/workspace/.exam-tools EXAM_BROWSER_TOOLS=/workspace/.exam-tools EXAM_BROWSER_EXECUTABLE=/usr/bin/chromium npm test
```

اگر Chromium نصب نیست، مرورگر رسمی Playwright را با دستور پشتیبانی‌شده آن نصب کنید. ابزارهای آزمون جزو وابستگی سایت نیستند. دستور ساده `npm test` بدون متغیرهای بالا، آزمون مرورگر و SQL را skip می‌کند. این آزمون‌ها با Auth شبیه‌سازی‌شده اجرا می‌شوند و اتصال واقعی Supabase را تأیید نمی‌کنند.

برای بررسی صریح سرویس واقعی، با `SUPABASE_ACCESS_TOKEN` امنِ همین پروژه:

```sh
python3 scripts/live-smoke.py
EXAM_BROWSER_TOOLS=/workspace/.exam-tools EXAM_BROWSER_EXECUTABLE=/usr/bin/chromium node tests/live-browser.mjs
```

این بررسی‌ها حساب و آزمون موقت ایجاد و فقط داده‌های همان اجرا را پاک می‌کنند؛ روی پروژه صحیح و محیط آزمون اجرا شوند. آزمون API و افزونه شامل ۳۳ بررسی واقعی Auth/RPC/Actions، ساخت آزمون با ابزار بسته و ثبت و تغییر نمره تشریحی است. آزمون مرورگر ۱۰ مرحله گردش واقعی برنامه را بررسی می‌کند. در محیط ابری فعلی، درخواست‌های مرورگر با کلاینت HTTPS مورد اعتماد Python به سرویس واقعی منتقل شدند؛ داده ساختگی جای پاسخ سرویس قرار نگرفت، اما TLS و preflight بومی Chromium در این مسیر تأیید نشده‌اند. این دو بررسی به‌صورت خودکار در `npm test` و GitHub Actions اجرا نمی‌شوند.

## انتشار روی GitHub Pages

در Settings → Pages منبع انتشار را **GitHub Actions** انتخاب کنید. پس از ارسال تغییرات به شاخه `main`، گردش `.github/workflows/pages.yml` فقط فایل‌های عمومی سایت را منتشر می‌کند. SQL و ابزارهای توسعه به سایت آپلود نمی‌شوند. این کار به‌تنهایی ساختار Supabase را نصب نمی‌کند.

## اتصال به ChatGPT

[بسته جدید افزونه Codex](downloads/exam-plugin-0.2.0.zip) را با **Upload new version** بارگذاری کنید. [راهنمای افزونه](plugin/README.md) مراحل نصب و تنظیم کلید شخصی `EXAM_TEACHER_TOKEN` در محیط امن اجرا را توضیح می‌دهد. ZIP شامل ابزار واقعی اتصال است و کلید یا رمز ندارد. تا درخواست بعدی صاحب پروژه، فایل ZIP در مخزن می‌ماند.

برای GPT سفارشی از [راهنمای GPT Actions](actions/README.md) و `openapi.yaml` استفاده کنید. معلم در پنل کلید اختصاصی می‌سازد و آن را فقط در تنظیمات احراز هویت Action وارد می‌کند؛ ChatGPT می‌تواند آزمون بسازد، نمرات حساب همان معلم را بخواند و نمره پاسخ تشریحی را ثبت یا تغییر دهد. رمز معلم نباید در گفت‌وگو وارد شود. هر معلم به کلید شخصی خود نیاز دارد؛ برای یک GPT مشترک چندمعلمه باید OAuth جداگانه پیاده‌سازی شود.

## رابط جدید و سرعت

ظاهر دسکتاپ و موبایل بازطراحی شده است. ثبت نمره بدون دریافت دوباره تمام پاسخ‌ها، حافظه موقت ۱۵ ثانیه‌ای برای رفت‌وبرگشت بین پنل و نمرات، و نمایش پاسخ‌ها هنگام بازکردن کارنامه باعث کاهش درخواست‌ها و حجم عناصر صفحه می‌شوند. برای دیدن پاسخ یا تغییر نمره‌ای که خارج از این زبانه ثبت شده، «به‌روزرسانی» را بزنید. [روش و نتایج آزمایش سرعت](docs/performance.md) را ببینید؛ در مقایسه کنترل‌شده، زمان ثبت نمره از ۸۴۳ به ۲۱۷ میلی‌ثانیه کاهش یافت.

## حدود نسخه فعلی

- دانش‌آموز با نام ثبت می‌شود؛ احراز هویت دانش‌آموز، جلوگیری از تکرار شرکت، محدودیت زمانی، مدیریت کلاس و ویرایش آزمون پیاده‌سازی نشده است.
- پاسخ‌های تشریحی را معلم تصحیح می‌کند؛ نمره نمایش‌داده‌شده تا آن زمان موقت است.
- پاسخ صحیح تستی در RPC عمومی آزمون برگردانده نمی‌شود. نمرات و پاسخ‌های دانش‌آموزان فقط برای مالک آزمون یا کلید فعال همان معلم قابل دریافت‌اند.
- پیش از استفاده عمومی، rate limiting و محافظت در برابر ثبت‌نام/ارسال پاسخ انبوه را در پروژه فعال کنید. مسیر عمومی ارسال پاسخ فعلاً CAPTCHA ندارد.
- نشست معلم در `sessionStorage` همان زبانه نگهداری می‌شود. کلیدهای Action را می‌توان از پنل لغو کرد.
- کد آماده‌سازی و آزمون‌های محلی، به معنی انتشار GitHub Pages یا نصب و تأیید پایگاه داده زنده نیست.
