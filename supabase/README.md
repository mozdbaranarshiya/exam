# راه‌اندازی پایگاه دادهٔ آزمون

این پوشه بخش سرور سامانه را فراهم می‌کند: ثبت مشخصات معلم پس از ساخت حساب Supabase Auth، آزمون، پاسخ دانش‌آموز، تصحیح تستی، نمره‌دهی تشریحی و کلید محدود برای اتصال GPT Actions. رمز عبور در جدول‌های سامانه ذخیره نمی‌شود و مدیریت آن با Supabase Auth است.

## نصب در پروژهٔ Supabase

پروژهٔ معرفی‌شده آدرس `https://pukanizbahswrupscfmg.supabase.co` دارد. کلید `publishable` برای اجرای SQL، تغییر تنظیمات Auth یا انتشار Edge Function مجوز مدیریت فراهم نمی‌کند؛ این کارها باید از Dashboard پروژه یا یک نشست مدیریتی معتبر CLI انجام شوند. کلید `service_role` را در سایت، GitHub Pages، مخزن یا چت قرار ندهید.

1. در Dashboard، بخش SQL Editor را باز کنید و محتوای کامل [مهاجرت اولیه](migrations/202610050001_initial.sql) را یک بار اجرا کنید. فایل در یک تراکنش اجرا می‌شود و برای PostgreSQL نسخهٔ ۱۳ به بعد نوشته شده است؛ افزونهٔ اضافی لازم ندارد. در پروژه‌ای که همین مهاجرت را اجرا کرده‌اید دوباره آن را اجرا نکنید.
   سپس [مهاجرت افزایشی نمره‌دهی API](migrations/202610060002_api_grading.sql) را یک بار اجرا کنید. برای پروژهٔ موجود فقط همین فایل جدید لازم است؛ داده آزمون‌ها و نمرات قبلی حفظ می‌شوند. ابزار `python3 scripts/apply-api-grading.py` با توکن مدیریتی امن، وضعیت ساختار را پیش از اجرای همین مهاجرت بررسی می‌کند.
2. در Authentication → Providers → Email، ورود با رمز عبور را فعال و **Confirm email** را غیرفعال کنید. سامانه با نام کاربری کار می‌کند و نشانی ایمیل داخلی آن واقعی نیست؛ با فعال بودن تأیید ایمیل ثبت‌نام کامل نمی‌شود. برای رمز عبور حداقل ۸ نویسه تنظیم کنید.
3. در Authentication → URL Configuration، مقدار Site URL را `https://mozdbaranarshiya.github.io/exam/` قرار دهید و همین نشانی را به Redirect URLs اضافه کنید.
4. مرورگر باید فقط آدرس پایهٔ پروژه و کلید publishable داشته باشد. `/rest/v1/` آدرس API جدول‌هاست و نباید جای آدرس پایهٔ پروژه برای Auth استفاده شود. راهنمای انتشار سایت و Actions در README اصلی و [راهنمای Actions](../actions/README.md) آمده است.

تنظیم تأیید ایمیل برای تمام حساب‌های یک پروژه اثر دارد. این سامانه برای یک پروژهٔ اختصاصی آزمون مناسب است. تریگر ثبت معلم فقط حساب‌هایی را پردازش می‌کند که دامنهٔ ایمیلشان `teachers.exam.invalid` است و به ثبت‌نام دیگر برنامه‌ها دست نمی‌زند.

## قرارداد حساب معلم

نام کاربری به حروف کوچک تبدیل می‌شود و باید ۳ تا ۳۲ نویسه شامل `a-z`، `0-9` یا `_` باشد. ثبت‌نام از این نشانی داخلی استفاده می‌کند:

```text
<username>@teachers.exam.invalid
```

دادهٔ ثبت‌نام Auth باید شامل `username`، `first_name`، `last_name` و `phone` باشد. نام و نام خانوادگی هرکدام ۱ تا ۱۰۰ نویسه و شمارهٔ همراه ۷ تا ۱۵ رقم با `+` اختیاری هستند. تریگر این اطلاعات را دوباره اعتبارسنجی می‌کند و یک پروفایل مرتبط با شناسهٔ Auth می‌سازد. شمارهٔ همراه اطلاعات ثبت‌شده توسط معلم است و در این نسخه با پیامک تأیید نمی‌شود.

ورود با همان ایمیل داخلی و رمز عبور انجام می‌شود. چون ایمیل واقعی دریافت نمی‌شود، **بازیابی رمز از طریق ایمیل در این نسخه پشتیبانی نمی‌شود**. برای بازیابی، مدیر باید هویت معلم را خارج از سامانه تأیید کند و سپس از ابزار مدیریتی Auth رمز را بازنشانی کند. اگر بازیابی خودکار لازم است، باید در توسعهٔ بعدی ایمیل واقعی یا ورود/بازیابی پیامکی اضافه شود.

## قرارداد آزمون و پاسخ

هر آزمون بلافاصله پس از ساخت قابل شرکت است. شناسهٔ آن یک عدد تصادفی ۱۲ رقمی است که در JavaScript دقیق باقی می‌ماند و در مسیر `/exam/id/<id>` قرار می‌گیرد. آزمون و سؤال پس از ساخت در این نسخه ویرایش نمی‌شوند تا بارم و پاسخ صحیحِ آزمون‌های پاسخ‌داده‌شده تغییر نکند.

آزمون ۱ تا ۱۰۰ سؤال دارد. عنوان حداکثر ۲۰۰، متن سؤال حداکثر ۵۰۰۰ و هر گزینه حداکثر ۱۰۰۰ نویسه دارد. بارم هر سؤال بیشتر از صفر و حداکثر ۱۰۰، با دو رقم اعشار است و مجموع بارم‌ها نباید بیشتر از ۱۰۰۰ شود. سؤال تستی دقیقاً چهار گزینه و یک پاسخ صحیح با اندیس صفر تا سه دارد:

```json
[
  {
    "type": "mcq",
    "prompt": "حاصل دو به علاوهٔ دو چیست؟",
    "points": 2,
    "options": ["۱", "۲", "۳", "۴"],
    "correct": 3
  },
  {
    "type": "essay",
    "prompt": "روش محاسبه را توضیح دهید.",
    "points": 3.5
  }
]
```

ورودیِ ساخت سؤال فقط شامل همین کلیدهاست؛ شناسه‌های موقت فرم نباید ارسال شوند. سؤال تشریحی `options` و `correct` ندارد یا مقدار آن‌ها `null` است. شناسهٔ دائمی هر سؤال را سرور ایجاد می‌کند.

پاسخ‌ها یک شیء با کلید UUID سؤال هستند. تمام سؤال‌ها باید دقیقاً یک پاسخ داشته باشند؛ شناسهٔ اضافی، گزینهٔ خارج از محدوده، بارم ارسالی توسط دانش‌آموز و متن خالی پذیرفته نمی‌شوند. پاسخ تشریحی حداکثر ۱۰٬۰۰۰ نویسه دارد:

```json
{
  "<mcq-question-uuid>": {"choice": 3},
  "<essay-question-uuid>": {"text": "توضیح دانش‌آموز"}
}
```

ثبت پاسخ اتمی است: خطای یک سؤال، تمام ثبت آن دانش‌آموز را برمی‌گرداند. سؤال تستی در سرور نمره می‌گیرد. وجود پاسخ تشریحیِ نمره‌نداده، وضعیت را `pending` نگه می‌دارد؛ پس از نمره‌دهی همهٔ آن‌ها وضعیت `graded` می‌شود. `total_score` در وضعیت `pending` فقط جمع نمره‌های موجود است، نه نمرهٔ نهایی. دانش‌آموز رسید دریافت می‌کند و پاسخ صحیح یا نمره‌ها در API عمومی نمایش داده نمی‌شوند. نام دانش‌آموز خوداظهاری است؛ شرکت مجدد یا تشابه نام ممنوع نشده است.

## توابع RPC

این توابع از `/rest/v1/rpc/<name>` فراخوانی می‌شوند. درخواست به کلید publishable نیاز دارد و توابع مخصوص معلم علاوه بر آن به نشست معتبر معلم نیاز دارند.

| تابع | پارامترها | خروجی / دسترسی |
| --- | --- | --- |
| `create_exam` | `p_title`, `p_questions` | معلم: `{id,title,created_at,question_count,total_points}` |
| `list_exams` | ندارد | معلم: آرایهٔ آزمون‌های خودش با تعداد سؤال، مجموع بارم و `submission_count` |
| `get_exam` | `p_exam_id` | عمومی: `{id,title,questions}`؛ سؤال‌ها فاقد `correct` هستند |
| `submit_exam` | `p_exam_id`, `p_first_name`, `p_last_name`, `p_answers` | عمومی: `{id,exam_id,status:"received"}`؛ فاقد نمره |
| `get_results` | `p_exam_id` | فقط مالک آزمون: سؤال‌ها، کلید صحیح و پاسخ و نمرهٔ دانش‌آموزان |
| `grade_answer` | `p_submission_id`, `p_question_id`, `p_score` | فقط مالک؛ فقط پاسخ تشریحی: `{id,total_score,status}` |
| `issue_api_token` | ندارد | معلم: `{token,expires_at}`؛ کلید خام فقط همین بار بازگردانده می‌شود |
| `revoke_api_tokens` | ندارد | معلم: `{revoked}`؛ همهٔ کلیدهای او باطل می‌شوند |
| `api_create_exam` | `p_token`, `p_title`, `p_questions` | کلید معتبر: همان خروجی `create_exam` |
| `api_results` | `p_token`, `p_exam_id` | کلید معتبر: نتیجهٔ آزمون متعلق به صاحب همان کلید |
| `api_grade_answer` | `p_token`, `p_exam_id`, `p_submission_id`, `p_question_id`, `p_score` | کلید جدید با مجوز نمره‌دهی؛ فقط پاسخ تشریحی همان معلم و آزمون: `{exam_id,submission_id,question_id,score,total_score,status}` |

`get_results` و `api_results` خروجی `{id,title,questions,submissions}` دارند. هر مورد `submissions` شامل `id`، `first_name`، `last_name`، `total_score`، `max_score`، `status`، `created_at` و `answers` است. هر پاسخ شامل `question_id`، `prompt`، `type`، `points`، `options`، `choice`، `text`، `score` و `correct` است؛ برای سؤال تشریحی، `choice` و `correct` برابر `null` هستند.

خطای اعتبارسنجی SQLSTATE `22023` دارد. نشست یا کلید نامعتبر `28000`، و دسترسی به آزمون/پاسخ دیگری `42501` است. برای جلوگیری از افشای مالکیت، آزمون ناموجود و آزمون متعلق به دیگری در توابع نتیجه هر دو پیام `Exam unavailable` دارند. `get_exam` و `submit_exam` برای آزمون ناموجود `P0002` بازمی‌گردانند.

## دسترسی و اتصال ChatGPT

برای تمام جدول‌ها RLS فعال است و دسترسی مستقیم `anon` و `authenticated` به آزمون، سؤال، پاسخ، نمره و کلید لغو شده است. فقط خواندن پروفایل خودِ معلم برای `authenticated` مجاز است. مسیر عمومی دریافت آزمون فقط محتوای سؤال‌ها را برمی‌گرداند. خواندن نتیجه و نمره‌دهی، مالکیت را داخل سرور بررسی می‌کند و توابع کمکی در اسکیمأ خصوصی قابل فراخوانی توسط کاربران نیستند. مسیر جست‌وجوی تمام توابع ثابت است.

کلیدهای قدیمی اجازهٔ ساخت آزمون و خواندن نتیجه را حفظ می‌کنند. کلیدهای صادرشده پس از مهاجرت جدید، مجوز `grade:essay` برای ثبت و تغییر نمرهٔ تشریحی همان معلم را نیز دارند؛ کلیدهای قبلی خودکار مجوز بیشتری نمی‌گیرند. برای نمره‌دهی از ChatGPT یک کلید جدید بسازید. نمره باید بین صفر و بارم سؤال با حداکثر دو رقم اعشار باشد؛ پاسخ تستی دستی تغییر نمی‌کند و همهٔ شناسه‌ها باید متعلق به همان آزمون باشند. هیچ کلیدی اجازهٔ مدیریت حساب ندارد. سرور فقط SHA-256 کلید را ذخیره می‌کند. کلید ۹۰ روز اعتبار دارد؛ حداکثر پنج کلید فعال برای هر معلم مجاز است و `revoke_api_tokens` همه را لغو می‌کند. کلید را در تنظیمات امن Authentication مربوط به GPT Actions یا متغیر شخصی امن `EXAM_TEACHER_TOKEN` محیط Codex قرار دهید. رمز ورود معلم را در گفتگو یا تعریف OpenAPI نگذارید.

## آزمون محلی مهاجرت

آزمون‌های [پایگاه داده](../tests/database.test.mjs) و [نمره‌دهی API](../tests/api-grading-database.test.mjs) مهاجرت‌ها و ۱۰۲ بررسی رفتار و دسترسی را در PostgreSQL واقعیِ PGlite اجرا می‌کنند: جداسازی دو معلم، حفظ مجوز کلید قدیمی، عدم تغییر مستقیم مجوزها، نبود پاسخ صحیح در خروجی عمومی، برگشت اتمی پاسخ نامعتبر، تصحیح تستی/تشریحی، تغییر نمره و صدور و لغو کلید. برای Auth، تابع `auth.uid()` و جدول `auth.users` شبیه‌سازی می‌شوند؛ این بررسی جای آزمون اتصال به Auth پروژهٔ واقعی را نمی‌گیرد.

ابزار آزمون بیرون از مخزن نصب می‌شود و وابستگیِ اجرای سایت نیست:

```bash
npm install --prefix /tmp/exam-sql-tools --cache /tmp/exam-npm-cache --no-audit --no-fund @electric-sql/pglite@0.5.8
EXAM_SQL_TOOLS=/tmp/exam-sql-tools node --test tests/database.test.mjs
```

بدون `EXAM_SQL_TOOLS` آزمون SQL با پیام روشن skip می‌شود. پس از اعمال مهاجرت و تنظیمات Auth در Supabase، ثبت‌نام/ورود معلم، ایجاد آزمون، ثبت پاسخ از مرورگر جداگانه و مشاهده/نمره‌دهی همان پاسخ از پنل معلم را در پروژهٔ واقعی هم بررسی کنید.
